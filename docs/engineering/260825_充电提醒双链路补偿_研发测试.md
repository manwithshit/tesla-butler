# 充电提醒双链路补偿：研发与测试记录

> 日期：2026-08-25
> 部署主机：M5
> 状态：代码、自动化、真实数据库只读联调和 M5 常驻部署完成；下一次真实充电端到端验收待完成

## 已部署方案

- MQTT 保留为实时链路，继续接收电量、功率、预计剩余时间和充电状态。
- Worker 每 60 秒只读 PostgreSQL 最新 `charging_processes`，并读取该会话最新一条 `charges` 作为补偿。
- 查询禁止并发重入，单次超时 3 秒；异常只记录失败，下一周期继续，不阻塞飞书消息和定时账单。
- MQTT 与 PostgreSQL 共用同一个充电会话状态、待发送队列和幂等键。
- 开始、即将达到设置上限、充电结束各最多推送一次。
- 飞书成功前不确认事件；临时失败、没有已登记会话或 Worker 重启后继续尝试。
- 充电结束卡展示充入电量、充电时长、电量变化和起止时间，并提示用户直接发送账单截图。
- 自研代码只读 TeslaMate 数据库，没有增加 Tesla API 轮询，也没有写入 TeslaMate。

- 充电专项：覆盖数据库漏报补偿、开始/结束状态、短会话、MQTT/数据库双源去重、旧结束事件不重放、3 秒超时、禁止并发、飞书失败重试、无会话等待和 Worker 重启恢复。
- Card 2.0：结束提醒通过结构检查，无返回菜单；已向现有飞书单聊发送一张明确标注“模拟数据”的结束卡片。

- 连续 20 次完整查询：中位约 81ms，P95 约 102ms，最大约 109ms。

### 既有真实联调

## 未完成与验收口径

- 2026-08-25 的真实充电发生在本方案部署前，只能证明 TeslaMate 数据库有记录，不能证明提醒已经端到端通过。
- 下一次真实充电必须验证：开始提醒延迟、即将达到设置上限的 ETA 准确性、结束提醒、每类只发一次、暂停/恢复不重复、完成后不再出现过期 ETA。
