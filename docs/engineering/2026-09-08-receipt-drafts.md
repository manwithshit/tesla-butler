# 充电账单草稿与文字补充

## 已实现

- 图片入口显式启用 partial 模式；严格识别接口默认行为保持兼容。
- 本地识别部分成功、不可用或识别出不安全页面时，都可返回可编辑草稿。
  不安全图片不拼接订单字段。草稿路径不调用云端兜底。
- 实付、电量、日期支持受限中文文字描述。未知字段不猜数值，仍需用户确认。
- 草稿保存在现有 receipts 存储中，状态 pending；仅存会话哈希和消息哈希。
  复用现有串行、原子写入机制；不创建新云服务，不保存文字原文。
- 有多个 pending 草稿时拒绝猜选；旧数据无归属哈希，不自动选为文字修改目标。
- 确认入口原子校验归属、revision、完整度；修改后旧卡失效。
  重复消息不重复追加草稿，已确认记录不接受文字覆盖。
- 卡片沿用项目现有 Feishu Card 2.0 样式，缺失字段给出补充提示，
  未通过校验的草稿不展示确认按钮，服务端同样禁止确认。

## 边界

- 只支持明确金额、电量及规范日期或今天/昨天/前天，不是通用自然语言模型。
- 文字修改清空旧单价、费用拆分与匹配结果；不自动重匹配 TeslaMate。
  未关联账单不会参与车辆行程电费分摊。
- 日期只有年月日时，按该日归账，不虚构充电时刻。没有日期仍沿用既有归账规则。
- 传输或存储失败时可能无法返回卡片，但会尝试文字反馈，提示重新发送。
- 未识别到的多订单模式仍有局限；用户确认不能替代后续识别准确性改进。

## 验证

完整 npm test：277/277；修改模块 node --check 与 git diff --check 通过。
新增 10 项测试覆盖 partial、OCR 故障、不安全图片、中文补充、日期、
多草稿、跨会话、旧卡版本、重复确认、消息重放、卡片发送重试、
菜单/默认电价路由、已确认记录保护。

测试使用内存存储边界及模拟消息发送，没有修改生产账本、发送消息、
启动云端识别或重启 Worker。代码只保留在本机隔离分支；
真实飞书端补充—确认的端到端验收须部署后由用户进行。
