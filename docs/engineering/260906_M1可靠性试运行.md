# M1 可靠性修复与本地试运行

基线：`edd6154`。本轮按用户授权在 M1 独立本地分支开发、测试和部署，暂不合并或推送 GitHub main。原有审查文件保留，不覆盖。

## 行为与实现

- MQTT 车门/锁车观察先写入本机 runtime-state 的 `trip_signal_inbox`，只保存内部事件标识、字段、布尔值、观察时间和 retained 标志。数据库与飞书操作不会阻塞信号持久化。
- 查库恢复后，将数据库行程开始/结束事实和信号按观察时间重放，再推进到当前时间。这样已完成的后续行程不会污染此前锁车边界。行驶中自动锁车、启动 retained、无行程锁车仍不能制造新行程。
- 信号消费和行程状态在一次原子文件替换中提交；未消费的新信号保留。写入失败会恢复内存状态。发送成功后的 ack 写入失败也保留相同幂等键供重试。
- 定时查库按队列键合并正在执行/等待的重复任务；真实事件保持顺序。周/月报告同一时刻只运行一次。退出时停止定时器并有界收尾。
- 普通文字/卡片查询失败最多重试一次，最终失败发送明确提示。事件只在 handler 完成后进入去重集合；处理中重复事件共享任务，抛错事件允许上游重新投递。账单与默认电价写入不经过查询重试器。
- 账单周期使用显式上海日历和 UTC 运算，不依赖主机时区；现有行程统计、默认电价和特殊电价规则保持不变。
- 菜单车辆状态查询最多等待 1.2 秒，超时取消查询并展示可用菜单与状态暂不可用说明。这个期限不包含飞书实际发送耗时。
- 正常地图命中缓存后不再查询原始轨迹；缺底图缓存五分钟后允许升级，同键并发请求共享渲染/上传。升级失败仍返回旧图并设置下次重试时间。
- 数据库操作强制只读，监控查询分为 SQL 6 秒、Docker 子进程 8 秒、外层 10 秒；外层取消会传到底层进程。错误日志仅包含安全查询名、阶段错误码、耗时和连续失败次数，恢复有单独记录。
- 飞书发送记录阶段、成功/失败和耗时；每分钟输出 consumer 数、MQTT 连接、队列长度、信号积压时间、最近查库成功距今时间，不记录事件内容或收件标识。

## 已知边界

- 只能保存已经被 Worker 收到的 MQTT 消息；TeslaMate 没发布或断网期间未送达的消息仍依靠原有充电/30 分钟停车兜底。
- 历史查询抖动原因尚不能从旧日志精确追溯，新的分层错误与成功时间用于后续定位，不能宣称已消除所有主机或 Docker 抖动。
- 飞书幂等键保持稳定，但客户端日志不能单独证明手机实际到达时间；真实消息送达和驾驶行为需后续验收。
- 冷启动地图仍需渲染与上传，本轮主要改善缓存命中路径、并发和降级恢复。
- 三笔旧账单不补关联；特殊电价仍等待新账单真实关联验收。
