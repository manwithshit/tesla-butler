## 一、项目为什么存在

项目最初来自一个面向小红书的创作问题：特斯拉车主开了很久以后，知道电车可能省钱，却很难直观看出自己究竟花了多少钱，以及相同里程换成不同油车要花多少钱。

早期讨论过驾驶建议、路线优化和能耗热力图。真实车主访谈后，主方向收敛为“把能源账翻译成人民币”：

- Tesla 实际跑了多少、估算耗电和行程电费是多少；
- 同样里程换成日产轩逸、宝马5系、路虎卫士、保时捷911和兰博基尼超跑，预计油费是多少；
- 行程结束、充电和周期账单通过飞书主动到达；
- 车主可以在自己的 Mac 上复刻，不把 Tesla 数据交给项目方服务器。

内容传播钩子是结果，不是技术栈：

> 原来我的电全耗在了这几段路上。
>
> 同样跑这些路，换成轩逸、宝马5系或保时捷911，分别要花多少钱？

产品既是一个真实可用的本地车主工具，也是小红书视频中的可验证演示。不能为了传播夸大历史数据、实时性、节省金额或授权能力。

## 二、当前产品定义

### 用户输入

- TeslaMate 在授权并持续运行之后采集的新行程、轨迹、车辆状态和充电会话。
- 用户在飞书单聊发送的充电账单图片；Apple Vision 本地 OCR 优先，K3 只在关键字段缺失时兜底。
- 用户确认后的账单才进入本地账本。

车辆与行程数据不接受截图、OCR 或手工录入。TeslaMate 无法补回安装前或离线期间的历史路线。

### 用户输出

- 行程小结：金额、电耗、里程、时长、起终点粗粒度道路、真实轨迹和相对能耗着色。
- 车辆概览：最后采集的电量、续航、状态和自然月行程汇总。
- 本周账单与本月账单：自然周期累计里程、耗电、行程电费和五档油车预计油费。
- 本月主跑路线：达到重复次数门槛后展示一条代表路线。
- 主动提醒：完整行程、开始充电、即将达到设置上限、充电结束、上周账单和上月账单。
- 手动菜单：上次行程、车辆概览、本周账单、本月账单。

### 五档油车锚点

飞书面向中国用户使用简称：

1. 日产轩逸
2. 宝马5系
3. 路虎卫士
4. 保时捷911
5. 兰博基尼超跑

后台计算版本、油耗、燃油标号和来源保存在产品文档与代码中。油费是统一参考口径的估算值，不是用户所在地某个油站的真实成交价。

## 四、已经锁定的工程规则

### 行程

- TeslaMate 的无时区时间按 UTC 解析，所有用户界面按 `Asia/Shanghai` 显示。
- 行程完成后等待 5 分钟稳定窗口。
- 同车、间隔不足 5 分钟且首尾不超过 100 米的片段合并。
- 中间充电、间隔达到 5 分钟或位置不连续时拆分。
- 首次启动只建立基线，不补发所有历史行程。
- 飞书成功后才确认事件；失败或 Worker 重启后继续尝试。
- 持久化事件不保存精确坐标。

### 充电

- MQTT 是低延迟主链路，PostgreSQL 每 60 秒补偿开始与结束漏报。
- 同一充电会话的开始、即将达到设置上限和结束各最多发送一次。
- 即将达到上限只使用当前会话两分钟内的新鲜 ETA；否则按距离上限不超过 5% 降级。
- 文案写“达到设置上限”，不能写“充满”。

### 账单与金额

- 行程电费是 `行程估算耗电 × 有效综合电价`，是估算值。
- 充电账单实付金额包含电费、服务费和可能的未拆分费用；不能伪造拆分。
- 油车只比较能源费，不包含购车、折旧、保险、停车或时间成本。
- 实际值、估算值和未知值必须明确区分。

### 隐私与车辆控制

- 自研代码只读 TeslaMate PostgreSQL，不写回 TeslaMate，也不发送车辆控制命令。
- 不得把 Owner API Token 宣称为细粒度只读 Token。
- Tesla 账号、密码、MFA、Token、VIN、精确住址、原始 GPS 和飞书 App Secret不得进入 Markdown、Git、聊天或日志。
- `data/raw/`、`data/processed/`、`infra/teslamate/.env` 和日志均不得提交 Git。

## 七、M1 后续修 Bug 的固定流程

每次开始前：

```bash
cd "$PROJECT_ROOT"
scutil --get ComputerName
hostname
sysctl -n machdep.cpu.brand_string
git status --short --branch
git pull --ff-only
npm ci
```

开发流程：

1. 先从当前日志、数据库只读查询或失败卡片确认问题，不把旧会话描述当成当前事实。
2. 新建 `codex/<bug-slug>` 分支。
3. 先写一个会失败的用户行为测试，再做最小修复。
4. 至少执行 `npm test`；涉及真实数据接口时追加对应 live 验证。
5. 执行 `git diff --check`，确认没有凭证、坐标、地址或本地数据进入 diff。
6. 提交、快进合并到 `main` 并推送 GitHub 仓库。
7. 只有当前机器已经完成 cutover、成为唯一线上主机时，才允许重启 Worker 做真实部署验收。

验证命令：

```bash
npm test
npm run test:live
npm run test:charging-live
npm run test:trip-live
```

`live` 检查会读取本机恢复的 TeslaMate 数据，因此 preflight 阶段只能证明代码能读取快照，不能证明 M1 已经实时采集或主动推送。
