# 主跑路线、菜单电量与充电提醒：研发与测试方案

> 日期：2026-08-25  
> 主机：当前 M5  
> 范围：本地 TeslaMate 只读、飞书单聊推送；不新增公共服务器，不调用车辆控制命令，不使用大模型。

## 交付

1. 本月/上月小结增加“本月主跑路线”或“上月主跑路线”。
2. 菜单直接展示电量、续航、车辆状态和数据更新时间，不新增按钮。
3. 充电状态优先从 MQTT 进入本地 Worker，PostgreSQL 每 60 秒补偿：开始、距离设置上限 15 分钟内、充电结束各提醒一次。
4. M5 服务部署完成；向现有飞书单聊发送模拟视觉卡片。

## 数据口径

### 主跑路线

- 只统计周期内已完成行程。
- 起终点距离在 750 米内视为同一端点。
- `A → B` 与 `B → A` 合并为同一往返走廊。
- 重复至少 3 次才标记为“主跑路线”。
- 优先按重复次数排序；相同次数按累计里程排序。
- 地图使用该组最近一次完整行程作为代表轨迹。
- 数据不足时显示“本月路线较分散”，不伪造路线。

### 菜单电量

- 数据来自 TeslaMate 最后一次已采集位置快照。
- 超过 10 分钟显示“最后记录”，不称实时。
- 车辆休眠/离线时不主动唤醒。

### 充电提醒

- MQTT 订阅 `battery_level`、`charging_state`、`charge_limit_soc`、`charger_power`、`charge_energy_added`、`time_to_full_charge`。
- Worker 每 60 秒只读最新 `charging_processes`，并从该会话最新一条 `charges` 补齐电量、功率和已充入电量；查询上限 3 秒，禁止并发重入。
- MQTT 与 PostgreSQL 共用充电会话状态和幂等键，任意一条链路先观察到事件都不会造成重复提醒。
- `charging_state = Charging` 的状态边沿触发开始提醒。
- `time_to_full_charge <= 0.25` 小时触发即将达到上限；剩余时间缺失时使用“距上限 <= 5%”降级。
- 新充电会话不得复用上一轮的剩余时间、充电功率和已充入电量。
- 即将达到上限只接受本次充电会话内、两分钟以内更新的剩余时间；降级电量判断同样要求数据新鲜。
- 实际发送前再次确认仍为 `Charging` 且会话未变；已 `Complete` / `Disconnected` 或暂停时取消排队提醒。
- 文案使用“达到设置上限”，不使用“充满”。
- PostgreSQL 观察到 `end_date` 后触发“充电已结束”，展示充入电量、时长、电量变化和起止时间，并提示发送充电账单截图。
- 每个充电会话三类提醒各最多一次；待发送事件先持久化，飞书成功后再确认。发送失败、没有会话或 Worker 重启均不会静默丢失。
- `Stopped`、`NoPower`、`Complete` 和 `Disconnected` 不混同。

## 实现边界

- PostgreSQL 继续只读。
- Mosquitto 仅映射到 `127.0.0.1`，不对局域网或公网开放。
- 运行状态只保存电量、充电状态、上限、功率、剩余时间和去重标识；不保存 VIN、Token 或 GPS。
- 模拟卡片明确标注“模拟数据”；模拟主跑路线不使用虚构 GPS。

## 测试方案

### L1：纯逻辑单元测试

- 往返路线合并、750 米边界、至少 3 次、次数/里程排序。
- 菜单新鲜/过期/无数据三种文案。
- 充电开始、15 分钟阈值、5% 降级、暂停/完成、重复事件、进程重启恢复。
- PostgreSQL 漏报补偿、MQTT/数据库双源去重、3 秒超时、并发检查、飞书失败重试和旧结束事件不重放。
- Card 2.0 P0–P7 结构和敏感字段排除。

### L2：本机集成测试

- 从当前 TeslaMate 4.1.1 读取真实车辆快照和真实月度行程候选。
- 连接本机 Mosquitto，发布隔离的测试主题验证订阅和状态机，不向飞书发送。
- 验证 PostgreSQL 无写入。

### L3：飞书验收

- 推送动态菜单模拟卡、月度主跑路线模拟卡、开始充电模拟卡、即将达到上限模拟卡。
- 回读最新消息，检查标题、关键字段、模拟标签、无菜单冗余和无敏感字段。
- Worker 重启后保持运行，错误日志为空。

### L4：下一次真实充电

- 验证真实 `Charging` 事件只推送一次。
- 验证 MQTT 没有广播时，PostgreSQL 补偿仍能在 60 秒轮询窗口内推送开始或结束提醒。
- 记录 TeslaMate 首次看到 `Charging` 的时间和飞书消息时间，验收两者延迟不超过 60 秒。
- 记录提醒时 TeslaMate / Tesla App 显示的预计剩余时间，以及实际达到设置上限的时间。
- 验证达到设置上限前只推送一次，暂停/恢复不重复。
- 强制验收：已完成充电后不得再出现“预计还有 15 分钟”类过期提醒。
- 实车验收日志只保存状态与时间差，不记录 VIN、Token 或位置。

2026-08-25 的真实充电已被 PostgreSQL 正常记录，但发生在双链路补偿部署之前，不能作为提醒端到端通过证据。下一次真实充电仍需完成 L4；不得把历史记录读取或模拟卡片描述成真实提醒验收。
