# 充电账单与 TeslaMate 充电记录关联

## 目标

用户可以在充电结束后晚些时候、甚至第二天发送账单。系统把账单费用事实与 TeslaMate 车辆充电事实做可审计的可选关联，让周结和月结按真实充电日期归账，同时避免错误自动关联。

## 产品规则

- PostgreSQL 的 `charging_processes` 是车辆充电时间和电量的事实来源；账单图片是实际付款、收费拆分和运营商的事实来源。
- 只检索账单收到前最近 7 天内已经结束的充电记录，不读取或展示车辆标识及位置。
- 账单含完整日期时，按上海时区比较时间；只有时分时，同时比较最近记录的上海时钟时间和充电电量。
- 候选只有一个且分数足够高时自动预选。候选相近时最多展示两个安全候选，由用户选择。
- 没有可靠候选时仍允许不关联记账。若账单只有时分，明确按收到日归账；不伪造精确关联。
- 关联只影响 `accounting_at` 和审计元数据，不覆盖 OCR 原始时间、账单金额或账单电量。
- 旧账单保持原结构并继续可读，不做批量迁移。新账单使用 schema version 3。

## 数据结构

新账单可增加：

```json
{
  "schema_version": 3,
  "fields": {
    "charged_at": "19:29",
    "charged_at_source": "time_only",
    "accounting_at": "2026-08-29 19:28",
    "accounting_at_source": "matched_session"
  },
  "charging_match": {
    "status": "matched",
    "selected_process_id": "...",
    "method": "automatic",
    "confidence": 0.85,
    "candidates": []
  }
}
```

`status` 为 `matched`、`needs_confirmation` 或 `unlinked`；`method` 记录自动选择、用户选择或用户跳过。候选仅保存内部记录号、结束时间、电量、分数和原因代码。

## 匹配与降级

总分由时间接近度和电量接近度构成。自动关联要求最高分至少 0.70，且与第二名至少相差 0.15；否则必须让用户选择。明显电量冲突不会自动关联。

TeslaMate 查询暂时不可用时，OCR 和记账仍可继续，卡片明确显示未关联。用户可见的卡片发送或账本写入失败继续使用现有明确反馈和重试逻辑。

## 验证范围

- 完整日期、只有时分、隔日发送、多个相近候选、无候选、明显电量冲突。
- 自动选择、人工选择、不关联确认、跨月归账、旧数据兼容。
- 本地 Apple Vision 完整日期解析、K3 降级不回归。
- 飞书卡片结构、确认/忽略动作和关联动作。
- 全量单元测试、语法检查、live-safe 数据库查询，以及部署后 Worker/consumer/容器健康检查。
