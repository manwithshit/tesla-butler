# 本地复刻与首次取数

日期：2026-08-23

## 产品决定

不接受 Tesla App 截图、OCR 或手工录入作为 1.0 输入。放弃历史数据的即时导入，换取本地授权后自动累积新数据。

## 推荐技术路径

```text
Tesla 车辆
   ↓ Owner API / streaming（个人车主当前可用，非官方 API）
TeslaMate 4.1.1
   ↓
PostgreSQL（本机行程、位置、充电数据）
   ↓ read-only
特斯拉小管家
   ├─ 单次行程
   ├─ 周结 / 月结
   └─ 用户自己的飞书机器人
```

Tesla Auth 0.15.0 只负责在本机 Tesla 原生登录流程中生成 Access Token 和 Refresh Token。它不存储行程，也不会因为“授权完成”就自动累积数据。

## 用户操作流程

1. 在自己的 Mac / NAS / Linux 设备上启动 TeslaMate、PostgreSQL、Grafana 和 MQTT。
2. 运行 Tesla Auth，用户仅在 Tesla 登录页输入账号、密码和 MFA。
3. 将生成的 Access Token / Refresh Token 粘贴到自己的 TeslaMate 登录页。
4. 确认 TeslaMate 已识别车辆，状态为 `online` / `asleep` / `driving`。
5. 保持宿主机唤醒且联网；新行程从此刻起入库。

Token 不得粘贴到聊天、Markdown、Git 或项目日志。最终教程的说法是“在自己电脑上完成 Tesla 授权”，不是“把 Tesla App 数据授权给我们”。

Owner API Token 不能认定为细粒度“只读 Token”。对外只能承诺“本项目的自研代码只读 TeslaMate 数据库，不发送车辆命令”，不能承诺“Tesla 只授予了读取权限”。

## 两天实测的成立条件

完成授权后，只有同时满足以下条件，新数据才会累积：

- TeslaMate 和 PostgreSQL 已启动并健康；
- M5 开车时没有睡眠或关机；
- M5 可连通 Tesla 中国 API；
- Token 未失效，TeslaMate 状态不是 `unauthenticated`。

只做授权、没启动 TeslaMate，不会记录任何数据。M5 睡眠期间错过的行程，Tesla API 不提供回填。

## 验收标准

1. `docker compose ps` 中 TeslaMate、PostgreSQL、Grafana、MQTT 均为运行状态。
2. TeslaMate 页面能显示车辆且正常进入 `asleep`，不持续唤醒车辆。
3. 一次真实短途后，PostgreSQL 新增一条完整 drive 和对应 positions。
4. 行程起止里程、时间和路线与真实行程一致。
5. 至少两次有效充电会话后，再验证 TeslaMate 估算的行程能耗。

TeslaMate 官方 FAQ 说明：Tesla API 不直接返回单次行程耗电；TeslaMate 需基于充电数据估算，至少两次充电会话后才首次显示估算值。

## 官方 API 迁移路径

当 Tesla 对个人账号关闭 Owner API，或项目需要变成公开多用户产品时，再迁移到 Fleet API / Fleet Telemetry。该路径需要开发者应用、公开 HTTPS 域名、公钥托管、车辆虚拟钥匙配对和公网遥测接收器，不符合当前“只在 M5 自托管”的约束。
