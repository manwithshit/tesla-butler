# Tesla 数据获取与历史数据调研

日期：2026-08-23

> [!INFO]
> 截图/OCR 方案已被产品决策否决。本文只保留“为什么授权也无法补回历史行程”的证据；当前技术选型见 [[260823_开源采集方案选型]]。

## 结论

1. TeslaMate 和 Fleet Telemetry 都只能从授权并成功运行之后累积数据，不能补回授权前的逐行程历史。
2. Tesla App 可见的历史充电统计，不等于官方 API 已开放同等导出能力。
3. Tesla 中国区 `charging_history` 文档当前仍标注“暂未开放，即将推出”。
4. 产品决定放弃历史导入，不再使用 Tesla App 截图、OCR 或手工录入。
5. 1.0 改为用户在自己电脑上授权，并从当天开始自动累积新行程。

## Tesla App 已有数据

Tesla 中国官方说明显示，“充电统计”可展示：

- 总充电次数、不同超级充电站、总充电量、预估总花费；
- 家庭、公司、其他和超级充电分类；
- 相对“可比较燃油车”的预估燃油费节省。

官方说明没有提供完整充电统计 CSV 导出。App 页面能看见历史，不代表 Fleet API 可以一次性导出同一套数据。

官方说明：https://www.tesla.cn/support/tesla-app/charge-stats

## 官方 Fleet API 的历史边界

### 可获取

- `GET /api/1/vehicles/{vin}/vehicle_data`：当前车辆状态，不是历史行程。
- Fleet Telemetry：授权并配置后，车辆向自建服务器持续推送信号。
- `GET /api/1/dx/charging/invoice/{id}`：按账单 ID 获取充电账单 PDF。

### 不能得到

- 授权前的完整历史行程列表；
- 授权前的逐秒 GPS 轨迹；
- 任意历史统计周期的起点里程表；
- 在采集器停止期间错过的 TeslaMate 行程。

## 为什么不直接用官方 OAuth 做当前 M5 原型

官方授权可行，但它需要：

- 在 Tesla 开发者平台创建应用；
- 公开 HTTPS 域名和 OAuth 回调；
- 托管指定公钥；
- 如果使用命令或 Fleet Telemetry，还需要车辆虚拟钥匙配对；
- Fleet Telemetry 接收器运行在公开互联网。

这与当前“每个用户只在自己电脑上运行，不依赖我们的服务器”相冲突。因此原型先使用 TeslaMate 当前为个人用户支持的 Owner API Token 路径，官方 Fleet API / Telemetry 保留为后续迁移方案。
