# 特斯拉车主数据工具｜小红书用户声音

> 调研日期：2026-08-25  
> 范围：MyTess、MyTesla、MyTes、特特管家、特斯拉数据、特斯拉能耗、特斯拉行程统计、特斯拉驾驶评分  
> 结论性质：小红书固定样本调研；不是全站普查，不代表全部车主

## 一句话结论

车主最缺的不是更多原始数据，而是三个翻译层：**这个数字算不算高、为什么高、对我意味着什么**。竞品已经覆盖行程、充电、电池、地图和通知；我们的合理差异化应是把这些数据压缩成一张主动送达、能直接看懂的“钱 + 路线 + 一句解释”小结，而不是继续堆字段或制造不透明驾驶评分。

## 采样与边界

- 8 个检索词，每个请求上限 15 条，共返回 120 条次，去重后 108 条笔记。
- 从中按产品名、数据/能耗/行程相关性选取 34 条抓取详情。
- 共抓取 365 条评论；剔除智驾测试、招聘、泛车辆讨论等偏题内容后，形成 259 条相关评论池。
- 检索结果时间范围：2021-09-26 至 2026-08-24。
- 评论聚类采用保守关键词规则；同一评论可能命中多个主题，数量不能相加为总需求人数。
- 页面显示评论数可能包含未被接口返回的回复；本轮评论抓取上限为每帖 50 条，因此高评论帖不是完整评论区。
- 产品官方/推广笔记只能证明“对方如何对外表达”，不能证明功能当前一定可用、准确或稳定。
- 小红书公开文本中没有找到 MyTess 或特特管家完整的“驾驶建议”原文。不能据此声称它们没有该能力，只能说本轮无可核验文本证据。

- `data/processed/research/xhs/search_results.json`
- `data/processed/research/xhs/note_details.json`
- `data/processed/research/xhs/comments.json`
- `data/processed/research/xhs/failures.json`（本轮失败数为 0）

所有链接均已去除 `xsec_token`；评论数据不保存评论者身份。

## 竞品在公开文本中如何表达

### MyTess

公开笔记使用的是“小而美、原生 iOS、实时、主动通知”的表达路线：

- 车辆当前状态、驾驶、停车、充电数据。
- 电池健康度。
- 峰谷电价自动记录充电费用。
- 车辆状态实时通知。
- 行程结束、充电完成、OTA、哨兵、月度报告、成就解锁通知。
- 充电与导航灵动岛：充电进度、功率、预计完成时间、导航距离、到达时间、预计到达电量。
- 日历、最高速度、各类 TOP 数据。

证据：

- [终于可以看特斯拉的详细数据了](https://www.xiaohongshu.com/search_result/698445d4000000001a022640)

它的表达优势不是“数据更专业”，而是把状态变成手机原生的即时反馈。弱点是相关产品帖互动量普遍较小，本轮不足以证明这些字段都有强需求。

- 充电记录、能耗趋势、异常提醒。

## 评论级需求聚类

以下数量来自 259 条相关评论池，按保守关键词匹配，主题间允许重叠。

| 主题 | 命中评论 | 用户真正要解决的问题 | 对产品的含义 |
|---|---:|---|---|
| 安装、连接与兼容摩擦 | 62 | 登录后无数据、不会配置、URL/Token/404、NAS/内外网、商店找不到、安卓不支持 | 这比新增字段更可能阻止使用；必须把“已连接、正在积累、暂无数据、连接失败”说清楚 |
| 能耗缺少参照 | 19 | 不知道数值是否正常、看不懂、怕自己开得太费电 | 不应只显示 Wh/km；至少给本次与个人基线/相似条件的比较，并翻译成钱 |
| 隐私、安全与费用 | 15 | 是否官方、是否安全、会不会更费电、是否收费、是否必须上云 | 本地存储、只读、数据从何而来、何时唤醒车辆必须在产品首屏可解释 |
| 路线与地图语义 | 7 | 只有经纬度没有中文地点、想要高德地图、轨迹好玩但价值不明、行程合并 | 地图必须有道路名称和起终点语义；纯折线只“好玩”，不够解决问题 |
| 视觉与暗色模式 | 6 | UI 风格不认可、仅白色不舒适、AI 味重 | 暗色可读性是基础能力；避免 3D 和装饰抢走核心金额/路线信息 |
| 主动行程通知 | 3 | 想恢复每次行驶后的通知、询问如何开启行程推送 | 样本小但方向明确；飞书主动送达是可用差异点，不应夸大成广泛刚需 |
| 历史数据 | 3 | 新注册能否看到注册前记录、能否看长期数据 | 初次使用必须明确“从何时开始有数据”，避免登录后全为 0 的落差 |
| 评分/建议标准不透明 | 3 | 不知道跟车、急刹、超速或激进转向为何扣分，认为误判 | 不做黑盒总分；每条建议必须给事件、位置、基线和不确定性 |

### 评论里最值得重视的三个矛盾

1. **用户想比较，但现有产品给绝对值。** 车主不断问“我的算高吗”，说明 140 Wh/km 不是答案，只是问题的开始。
2. **用户想要解释，但评分系统给结论。** Safety Score 相关评论集中质疑扣分标准和误判。黑盒评分会把“建议”变成责备。
3. **用户想少操作，但第三方工具先要求复杂部署。** 特特管家相关评论大部分在问如何连接、为什么无数据、是否必须买云服务；这会吞掉后续功能价值。

## 对当前产品的优化建议

本节只给建议，本轮不实施。

### P0：小结字段只保留一个决策链

推荐顺序：

1. **本次预计花了多少钱**：第一视觉锚点。
2. **行驶里程、估算电耗、行驶时长**：解释金额的三项事实。
3. **路线地图 + 道路名称 + 起止时间**：说明这笔消耗发生在哪里。
4. **同条件参照**：优先比较“你的个人常态”或“同一路线历史”，再展示油车金额对比。
5. **一句本次解释**：只说最值得行动的一件事。

“同距离油车预计花多少钱”在本轮小红书评论里没有形成直接高频证据；它仍是很强的内容表达假设，但证据主要来自此前真实车主访谈，不能伪装成小红书共识。建议保留并继续用真实用户测试验证。

### P0：驾驶建议改成“可核验事件”，不要做总分

公开小红书样本没有取得竞品完整建议文案；可从用户对评分不透明的反感，反推出最低表达标准：

- 先写位置：`在 XX 路驶入 XX 路后的 1.2 km`。
- 再写观察：`这一段单位能耗比你本次平均高 28%`。
- 再写可验证原因：只有确有速度、海拔、温控或拥堵证据时才写原因。
- 最后给动作：`下次进入该路段前提前松电门，保持更平稳的加速`。
- 原因证据不足时写：`暂时无法区分拥堵、坡度与空调影响，不给驾驶结论`。

不建议：

- “红色高消耗段集中，请降低电门。”——没有时间和道路锚点。
- “本次驾驶 72 分。”——标准不透明，用户无法复现。
- 仅凭高能耗建议开启自动驾驶——能耗不能证明人工驾驶是原因，也不能替代安全判断。

建议文案模板：

> 在【道路 A → 道路 B】后的【距离】内，本段单位能耗比你本次平均高【比例】。已观察到【可核验因素】；下次可在【具体动作时机】提前【动作】。若原因不足，则明确写“本次只提示异常路段，不判断驾驶习惯”。

### P0：把“是否正常运行”当作字段

评论里最强痛点是“登录后为什么全是 0”。每张首次使用页面应明确显示：

- TeslaMate 已连接 / 未连接。
- 数据开始积累时间。
- 最近一次成功同步时间。
- 暂无行程是“没有新行程”还是“采集异常”。

这些是信任字段，不是设置页技术信息。

### P1：地图从“轨迹装饰”升级为“道路叙事”

- 地图保留热力轨迹，但正文必须出现道路名称，而不是经纬度或“所在区域”。
- 起点、终点、最高消耗段各有明确标记。
- 周/月卡片不叠加全部轨迹；改成“最高花费的一次行程”或“最常走路线”的单条地图。
- 分享图默认模糊家庭、公司与精确起终点。

### P1：主动推送保持克制

- 行程结束：仅推一张可忽略的小结，无菜单按钮。
- 周/月：突出累计里程、总电量、真实/估算花费、油车预计花费。
- 充电结束：展示实际支付、充入电量、服务费拆分和本次综合电价。
- 不推哨兵、OTA、胎压等与 1.0 “省钱小票”无关的状态，避免复制 MyTess 的完整车辆管家路线。

### P1：视觉层级优先于炫技

- 第一层只允许一个主数字：本次花费或本期省下的钱。
- 第二层 2×2 指标卡；深色模式降低纯白高光，使用中等对比度数字。
- 第三层地图；颜色只承载能耗高低一种含义。
- 第四层一句解释；不放技术口径、坐标纠偏、模型名。
- 3D 车辆、排行榜、成就、TOP 数据不进入 1.0。

## 字段取舍建议

| 字段 | 建议 | 依据 |
|---|---|---|
| 预计花费 | 置顶 | 比 Wh/km 更容易理解；但油车金额对比仍需继续验证 |
| 行驶里程 | 保留 | 构成金额和对比的基础 |
| 估算电耗 | 保留并标“估算” | 必须与实际充电账单口径区分 |
| 行驶时长 | 保留 | 帮助理解拥堵和短途高耗 |
| 出发—结束时间 | 合并一行 | 减少字段碎片，支持路线叙事 |
| 所在区域 | 删除 | 道路名称与地图已提供更具体语义 |
| 平均/最高车速 | 默认不展示 | 竞品有该字段，但评论需求弱，且易喧宾夺主 |
| 动能回收量 | 默认不展示 | 专业但不直接转化为行动或金额 |
| 电池健康 | 不进入行程小结 | 属于车辆概览，不是省钱小票主任务 |
| 驾驶总分 | 不做 | 评论明确反感不透明评分 |
| 道路级异常段 | 有可靠定位后再展示 | 用户需要具体地点，但原因归因必须谨慎 |

## 可验证的下一步

1. 用真实行程对 3 种卡片做车主测试：只显示电耗、显示个人基线、显示油车金额；问用户 5 秒后记住了什么。
2. 对道路级建议做准确性验收：道路名称、方向、路段边界是否与实际驾驶一致；任何一项不稳，就只显示异常路段，不下建议。
3. 在飞书暗色模式和白天模式分别验收主数字、地图图例和正文可读性。
4. 新用户冷启动测试只看三件事：是否知道数据从何时开始、是否知道正在积累、是否知道下一次什么时候会收到小结。

## 证据强弱总结

- **强证据**：车主看不懂绝对能耗，需要参照和解释；第三方工具部署/连接摩擦大。
- **中等证据**：地图需要中文道路语义；隐私、安全、耗电和收费会影响采用。
- **弱但方向一致**：每次行程主动推送、暗色模式、历史数据、道路级建议。
- **本轮未验证**：用户是否愿意长期看“同距离油车花费”、驾驶建议是否真的改变行为、竞品建议文案的具体写法。
