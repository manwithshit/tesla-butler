# Mytess 与特特管家：公开资料与 App Store 调研

> 调研日期：2026-08-25  
> 范围：中国区 App Store、Apple 公开元数据与评论、应用官方页面/文档、开发者公开产品文章。  
> 边界：只提出产品建议，不修改产品。本报告没有登录应用，也没有验证真实车端采集结果。

## 结论

1. 用户所说的“MyTess”准确名称是 **Mytess**，App Store ID 为 `6757828502`。另一款为 **特特管家-特斯拉车主必备**，App Store ID 为 `6738431519`。
2. **“行程建议”并不是两款竞品都已经做好了的成熟能力。**
   - Mytess 的公开设计是：仅在检测到明确模式时生成“洞察胶囊”，用“原因/事件 → 风险或意义 → 一个动作”表达；不强制每程输出，也避免武断诊断。
   - 特特管家的商店截图中，“AI 驾驶评价”主要是能效、均速、最高速度、功率等指标的串联和一个 `72 分`，没有看到可执行建议，更没有道路/路口级建议。
3. Mytess 已公开提供油电对比、节省金额、周/月回顾、充电费用、同路线能耗对比和分享卡。**油电对比、周期推送、地图轨迹本身都不能再视为独家差异。** 我们更值得保留的差异是：飞书中自动收发、真实账单补全、相同里程直接换算成不同油车的“钱”、一张即读的小票。
4. 视觉上，Mytess 的优点是“一屏一个任务、一个主数字、场景优先级”；特特管家的行程页是 `3×3` 指标网格，更全，但接近仪表盘。我们的飞书卡不应继续加字段，而应保持“地图 + 4 个核心数字 + 1 条可信结论”。
5. 驾驶建议建议保留，但必须改成 **“有证据才说；说不准就不说”**。道路名只能来自可靠的轨迹道路匹配；不能把高能耗直接等同于驾驶激进，也不能仅凭功率推断应如何踩电门。

## 三、“驾驶建议”怎么写

### Mytess：条件触发的洞察，而非每程评分

官方公开的洞察包括：

- 安全距离：高速急刹车事件提示，建议增加跟车距离。
- 低温动能回收：电池温度影响回收时提醒，建议出发前预热。
- 能效黄金脚：对高效驾驶作正向反馈。
- 爬坡能耗：说明上坡消耗和下坡回收，解释地形影响。
- 公开产品文章另提到高峰舒适度等评价徽章。

官方截图中可读到的实际文案是：

> 低温回收受限：电池低温导致动能回收受限，请留意刹车距离。

它的结构不是“能耗高，请轻踩”，而是：

`检测到的条件（低温） → 对车辆行为的影响（回收受限） → 用户动作（注意刹车距离）`

更重要的产品规则：

- 并非每一次驾驶都会生成洞察；只在检测到特定模式时出现。
- 可有多条洞察，但以胶囊轮播，不在首屏堆满。
- 开发者公开说明会避免“武断诊断”，因为采样间隔、天气、路线和驾驶习惯都会影响能耗；应展示证据和数据不足。

来源：[Mytess 官方功能文档](https://www.mytess.net/zh/docs/guide)、[Mytess 2.0 开发者说明](https://cn.v2ex.com/t/1225226)、本地官方截图 [`mytess/3.png`](../../data/processed/research/appstore/mytess/3.png)。

### 特特管家：公开截图更接近“数据摘要 + 总分”

商店截图中的完整可见文案为：

> 能效 134.8，平均速度 31.8，最高速度 105，功率 135，无续航降低。评分：72 分。

这段话存在三个问题：

1. 指标被拼成一句话，但没有说明它们与 `72分` 的关系。
2. “无续航降低”语义不清，不能指导下一次怎么开。
3. 没有时间、道路、事件锚点，也没有可验证证据。

特特管家 `2.8.0` 已公开“红绿灯识别与通行效率评分”，说明它在向道路场景靠近；但仅从公开资料无法确认评分算法、文案模板和准确率。不能把这一能力描述成已验证成熟。

来源：[特特管家中国区 App Store](https://apps.apple.com/cn/app/%E7%89%B9%E7%89%B9%E7%AE%A1%E5%AE%B6-%E7%89%B9%E6%96%AF%E6%8B%89%E8%BD%A6%E4%B8%BB%E5%BF%85%E5%A4%87/id6738431519)、本地官方截图 [`tete/4.png`](../../data/processed/research/appstore/tete/4.png)。

### 推荐给我们的文案模型（只建议，不实施）

推荐固定为四段式，并允许整段缺席：

`道路/时间锚点 → 观察到的事实 → 合理解释与不确定性 → 下一次一个动作`

示例结构：

> 18:42–18:45，从 A 路转入 B 路后，单位里程耗电明显高于本次平均。这里同时出现低速走停，暂不能判断是急加速还是拥堵造成。下次经过这段路，优先保持平缓跟车；如果仍然偏高，再和同路线历史行程比较。

约束：

- 没有可靠道路匹配：只说时间段，不编道路名。
- 能耗偏高但无法排除上坡、空调、低温、拥堵：写明不确定，不归因于“驾驶激进”。
- 没有显著异常：不输出建议，改为一条正向事实或直接省略。
- 不给总分。使用“低温回收 / 拥堵走停 / 高效区间 / 数据不足”等可解释标签。

## 四、视觉表达对照

### Mytess

- iOS 原生、白底、蓝色单一主色，留白较多。
- 页面以卡片分组；每张卡有一个大数字和 2–4 个辅助值。
- 首页内容按车辆当前状态自动排序：充电时充电置顶，刚结束驾驶时行程置顶。
- 地图承担“故事锚点”，统计负责“结论”；两者不在同一屏争抢。
- 周/月使用环比小标签、洞察气泡和分享海报，不把所有原始字段放在一张表。
- 风险：功能已经很深，官网/商店文案出现“数据洞察”“有温度”“故事”等大量抽象包装；我们不应照搬语言。

### 特特管家

- 主页以 3D 车模和多入口宫格吸引注意，字段覆盖更广。
- 单程详情采用地图 + `3×3` 彩色指标格 + 多条曲线，适合主动探索，不适合被动推送。
- 月历把驾驶日、充电日、当日里程直接编码在日期上，可快速扫规律。
- 公开评论同时出现“UI 变帅/直观”和“UI 有点丑/希望升级设计”，审美反馈不一致；不能只根据单条评论下结论。
- 最新版本新增路线按速度变色，这说明“彩色轨迹”已不是独占表达。我们的颜色应表达用户关心的钱或能耗，并配清晰图例。

### 对飞书卡的建议（只建议，不实施）

1. **行程卡：** 地图作主视觉；地图上方 4 个数字（费用、耗电、里程、时长）；地图下方只放时间范围、路线概览和一条洞察。
2. **周卡：** 一个大数字回答“这周实际/估算花了多少钱”，第二层是里程和耗电，第三层用五台油车直接显示同里程预计油费。
3. **月卡：** 只选一个最可传播的主结论，例如“这个月比开宝马 5 系预计少花 ¥X”；其余数据降级为证据。
4. **暗黑模式：** 避免发光数字、浅灰字和大面积透明玻璃效果。飞书卡以系统可读性为准，不照搬 App 的 Liquid Glass。
5. **地址隐私：** 分享图默认模糊起终点附近区域；卡片内可看路线，外发图片隐藏具体地址。

## 五、65 条中国区 App Store 公开评论暴露的需求

本次读取 Apple 中国区公开评论 RSS：Mytess `35` 条、特特管家 `30` 条，共 `65` 条。它们不是随机抽样，也不代表全部评分者；只用于发现表达和问题，不用于估算需求占比。

### Mytess 评论中的高频价值表达

- “车机/Grafana 里难找，手机上直接看历史能耗和里程。”
- “费用不再是感觉：分时电价、每公里成本、充电账单。”
- “地图不是轨迹表，而是驾驶纪念册/回忆。”
- “数据在自己的 TeslaMate 服务器，隐私安心。”
- “UI、图形化、优先级排序、灵动岛让数据变成随手可看。”
- 负面样本集中在付费层级理解：一条一星评论认为云服务、Web UI、App PRO 多次收费，说明不同费用口径必须提前讲清楚。

样本结构：35 条可见评论中 `34` 条五星、`1` 条一星，高度偏正向。只能说明当前可见评论的表达，不能用作普遍满意度结论。

### 特特管家评论中的具体诉求

- 行程结束、充电完成后要及时推送；推送失效会直接损害核心体验。
- 希望按“天”先看总行程次数/总里程，再进入单次明细。
- 充电费用要支持地点/电价差异，并在充电后形成账单。
- 单次行程希望直接看到费用。
- 地图轨迹的加载速度和精度比字段数量更重要。
- 所有首页字段要共享清晰的“最后更新时间”，避免时间语义误解。
- 强烈要求解释服务器、Token 和推送数据的处理方式。
- 需要稳定性：闪退、小组件为 0、通知失效、AI 偶发异常都会让数据功能失去信任。

样本结构：30 条可见评论中 `21` 条五星、`4` 条四星、`1` 条三星、`2` 条二星、`2` 条一星，问题信息比 Mytess 样本更丰富。

## 六、隐私与可信度检查

### Mytess

- App Store 开发者声明为“不收集数据”。
- 隐私政策说明车辆位置、行程、充电、Tesla 账号、API 地址/凭据不上传其服务器；API 配置保存在 iOS 安全存储；可能使用 Apple 匿名崩溃/使用分析。
- 官网另有 Mytess Cloud。自建与云托管的数据路径不同，面向用户时必须分别说明，不能用“所有数据始终只在本机/自建服务器”概括全部方案。

来源：[Mytess App Store](https://apps.apple.com/cn/app/mytess/id6757828502)、[Mytess 隐私政策](https://www.mytess.net/privacy)、[Mytess 官网部署选择](https://www.mytess.net/zh)。

### 特特管家

- App Store 开发者声明为“不收集数据”。
- 其公开隐私政策同时写有“注册用户账号”“记录账户名、密码、联系方式”“可能短信或邮件验证”等内容。
- 中国区评论还出现用户对后台可见数据、App 关闭后仍能接收车辆推送的质疑。这些评论不能证明实际违规，但和当前商店声明、隐私政策存在明显解释缺口。

结论：**不能据此断言特特管家实际收集了什么；可以确认其公开隐私表达不一致，用户无法仅靠这些文本理解数据路径。** 这也是我们应明确本地采集、只读数据库、飞书推送和图片识别数据边界的原因。

来源：[特特管家 App Store](https://apps.apple.com/cn/app/%E7%89%B9%E7%89%B9%E7%AE%A1%E5%AE%B6-%E7%89%B9%E6%96%AF%E6%8B%89%E8%BD%A6%E4%B8%BB%E5%BF%85%E5%A4%87/id6738431519)、[特特管家隐私政策](https://tesla.funtao8.com/Policy.html)、[特特管家中国区公开评论 RSS](https://itunes.apple.com/cn/rss/customerreviews/page=1/id=6738431519/sortby=mostrecent/json)。

## 七、面向当前产品的优先级建议

以下均为调研建议，本轮不实施。

### P0：直接影响定位与可信度

1. 不再把“地图、周月报、油电对比”当作唯一卖点；定位改为“飞书里自动到账的真实省钱小票”。
2. 周/月核心语句固定回答钱：`本期电车花费`、`同里程五台油车预计油费`、`差额`。
3. 驾驶建议只在有证据时出现；不用黑箱总分，不把高能耗直接归因到用户。
4. 任何费用都标注 `实际 / 估算 / 未知`；避免竞品评论中“账单到底怎么算”的信任问题。
5. 分享图默认脱敏起终点；说明 TeslaMate、本地账本、视觉识别和飞书各自处理什么数据。

### P1：提高读懂速度与传播性

1. 单程只保留地图、4 个主指标、时间/路线、1 条洞察。
2. 路线颜色只表达一个维度；建议优先“单位里程电费/能耗”，图例写成人话，不同时叠速度、功率、拥堵。
3. 月报用一个 Hero 结论，不做字段墙；例如“本月开了 X 公里，预计比宝马 5 系少花 ¥Y”。
4. 加“与上周/上月的自己比较”，但只显示变化显著且口径完整的指标。
5. 道路级建议必须提供时间锚点；道路匹配不可靠时降级为时间段。

### P2：有数据量后再做

1. 同路线近期行程对比，区分天气、拥堵、空调和驾驶因素。
2. 按日汇总再下钻单次，解决多段短行程过碎。
3. 个人成就/回忆只保留与省钱相关的少数项目，不复制竞品的完整徽章系统。
